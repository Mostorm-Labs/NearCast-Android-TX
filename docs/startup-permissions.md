# 启动权限检查

每次新建应用界面时读取实际系统权限。首次引入此功能，或必要的音频权限缺失时，显示统一的“投屏权限检查”；已有采集或正在申请采集的会话不被引导打断。必要权限仍有效时，后续启动只检查，不重复弹窗。设置中可随时重新查看。

| 项目 | 启动检查与操作 |
| --- | --- |
| 屏幕采集（必需） | 未采集时显示“每次投屏时确认”；当前采集有效时显示“本次共享已授权”。启动检查不请求 MediaProjection，不开始采集，也不保存可重复使用的授权。 |
| 系统声音（当前管线必需） | 读取 `RECORD_AUDIO`；缺失时可在引导中请求。说明用途为共享系统播放声音，不采集麦克风。永久拒绝时提供应用设置入口。 |
| 通知（可选，API 33+） | 读取 `POST_NOTIFICATIONS`；可请求或前往应用设置。拒绝不阻止继续投屏，正常投屏链不反复强求。 |
| 接收端反控（可选，API 26+） | 检查无障碍授权和服务实际连接。用户主动开启时显示用途说明并前往公开系统设置入口。未开启不阻止投屏。 |

引导中可在必需音频权限就绪后继续，或选择“稍后设置”。一次界面启动内的返回和重建不会重新拉起已跳过的引导；下次真正启动仍会检查缺失的必需权限。从系统设置返回后重新读取状态，不把成功打开设置页当作已授权。系统权限请求按顺序执行，等待结果时禁止重复请求或关闭引导。

启动音频/通知权限使用独立 Activity Result launcher。它的结果只刷新权限状态，不能进入连接会话的屏幕采集请求；原有 MediaProjection chooser、前台服务启动顺序、会话 ID 和请求取消检查保持不变。

Android 的屏幕采集授权不是 macOS 那样的常驻开关。[Android 官方说明](https://developer.android.com/media/grow/media-projection)要求每次新建采集会话获得同意；API 34+ 不得重复使用同一授权 Intent 获取 MediaProjection，也不得在同一 MediaProjection 上重复创建 VirtualDisplay。因此“每次投屏时确认”不能缓存为一个持久的已授权状态。

## 2026-11-19 真机验证

使用 Pixel 7 / Android 17 的全新独立调试包，验证首次引导、声音权限拒绝后的返回和再次请求、永久拒绝后的应用设置入口，以及在系统设置允许后返回更新为“已授权”。继续按钮在必需音频未授权时不可用，授权后可用；通知拒绝且无障碍未授权仍可继续。冷启动不会因可选权限缺失而重复打开引导。整个过程 MediaProjection 均为 null，未在启动检查或权限返回时触发录屏。独立测试包已清理，原调试包的授权未被撤销。
